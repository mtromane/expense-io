# ADR-012 · 401 si non connecté, 403 si connecté sans le rôle

* Statut : Acceptée (équipe, 2026-10-26)
* Décision source : D12 (`B-01`, `B-02` ; défauts `AUTHZ-01`, `AUTHZ-02`)

## Contexte
L'application d'origine renvoyait `401` à un utilisateur connecté au mauvais rôle sur `/api/manager/*` et `403` à un anonyme sur `/api/hr/*`. Les tests de parité figeaient cette incohérence.

## Décision
Appliquer le standard HTTP (RFC 9110) dans la garde unique `route()` : pas de session → `401 Unauthorized`, session sans le rôle exigé → `403 Forbidden`. Le paramètre `deniedStatus` des routes disparaît.

## Alternatives
* Conserver : aucun test à toucher, mais contraire au standard et très probablement un des tests rouges du professeur.

## Conséquences
* Une seule modification dans `shared/http/route.ts` au lieu de 13 fichiers : démonstration directe du bénéfice de la garde centralisée.
* Les cellules concernées de `tests/api/authz-matrix.ts` passent par le cycle défaut rouge → vert ; `docs/api/openapi.yaml` documente `403` sur `/api/manager/*` et `401` sur `/api/hr/*`.
